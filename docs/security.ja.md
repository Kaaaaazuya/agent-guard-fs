# セキュリティ

[English](security.md) | 日本語

このページは、AgentGuard FS が防ぐもの、防がないもの、利用前に知っておくべき制約を説明します。
判定の仕組みは [policy.ja.md](policy.ja.md) を併せて読んでください。

## 用途

AgentGuard FS は、AI エージェントが MCP 経由で実行できるファイル操作を制限します。
エージェントがファイルに触れる手段がこのサーバーだけの場合に役立ちます。エージェントにシェルや、
同じディレクトリを読み書きできる別のツールがあれば、ポリシーは迂回されます。その場合、AgentGuard FS はファイルを守れません。

サンドボックスではありません。起動したユーザーと同じ OS 権限で動作します。
コンテナ、別アカウント、ファイルのパーミッションの代わりにはなりません。

## 信頼の前提

- サーバーを起動する人がルートを選び、ポリシーを書きます。この人は信頼されています。
- エージェントは信頼されていません。どんなパスでリクエストしてくるかわからないものとして扱います。
- ポリシーファイルは信頼できる人が管理し、ルートの外に置きます。

## 防ぐもの

| 脅威 | 対策 |
|---|---|
| `..`、絶対パス、`\` によるルート外へのアクセス | ポリシー判定の前にパスを検証して拒否する。ファイルはルートのディレクトリ記述子からの相対で開く。 |
| ルート内の symlink を経由して保護対象に届く（例: `src/leak -> ../.env`） | パスのどの要素にある symlink も拒否する。検査と open は 1 回のシステムコールで行う。Linux は `openat2` の `RESOLVE_BENEATH \| RESOLVE_NO_SYMLINKS`、macOS は `O_NOFOLLOW_ANY` 付きの `openat`。 |
| 検査と open の間にパスを symlink に差し替える | 検査と open は 1 回のシステムコール。書き込みと削除は親ディレクトリの記述子に対する `openat`、`renameat`、`unlinkat` で行い、パスを解決し直さない。 |
| `.ENV` や分解された `é` など、保護対象名の大文字小文字や Unicode の違い | deny の照合は NFC と Unicode の case folding で行う。 |
| ポリシーを緩めて再起動する | 起動時に、解決後の実体パスがルートの内側にあるポリシーを拒否する。ルートの外からの symlink 経由も含む。 |
| 部分的な書き込みや壊れた書き込み | 同じディレクトリの一時ファイルに書き、同期してから対象へ rename する。失敗やキャンセル時は一時ファイルを削除する。 |
| 巨大な読み書きによるメモリやディスクの枯渇 | サイズ上限（`maxReadBytes`、`maxWriteBytes`）を I/O 層で強制する。読み取りは上限を 1 バイト超えた時点で止める。 |
| 特殊ファイル（デバイス、FIFO、ソケット）や symlink を操作対象にする | 通常ファイルとディレクトリだけを操作する。それ以外は `unsupported_file_type` を返す。 |
| エージェントが、サーバー自身の一時ファイル名と同じ名前を使う | `.agentguard-tmp-*` の形の名前は、どの操作でも拒否し、一覧にも出さない。 |
| ログからの秘密の漏えい | 監査記録には、時刻、操作、相対パス、判定、ルール名、結果、所要時間だけを入れる。ファイル内容は入れない。エラーの文面には絶対パスや内容を入れない。 |
| プロトコルの破損 | 標準出力は MCP メッセージだけに使う。ログは標準エラー出力に出す。 |

## 失敗時の挙動（fail closed）

- ポリシーの読み込みや検証に失敗すると、起動しません。代わりのポリシーで続行することはありません。
- カーネルが symlink をたどらずにディレクトリを開けない場合、起動を拒否します。より弱い方式には切り替えません。
- ガード内の予期しないエラーは `internal_error` にマップし、操作は実行しません。
- ポリシー判定が失敗したパスは拒否します。

## 残存リスク

以下は既知の制約です。隠さずに記載しています。

### ハードリンク

ルート内のハードリンクは、別の名前から同じファイルを指します。パスだけでは区別できません。
保護対象のファイルに許可された名前のハードリンクがあると、許可された名前の読み取りで保護対象の内容が返ります。
MVP ではハードリンクを検出しません。

対策: 保護対象のファイルはルートの外に置くか、ルート内に別名のハードリンクがないことを確かめてください。

### bind mount と特殊なファイルシステム

ルート内の bind mount は、ルートのパスからはポリシーで見えないファイルを露出させることがあります。
`/proc` などの特殊なファイルシステムを通したアクセスも防ぎません。特殊ファイル（デバイスなど）の種別は拒否しますが、
それ以外の経路は対象外です。

対策: ルート内に bind mount を置かず、`/proc` などを通して保護対象のデータにルートから届く場所でサーバーを動かさないでください。

### エージェントが使えるほかのツール

前述のとおり、エージェントがこのサーバー以外でファイルにアクセスすれば、ポリシーは迂回されます。
これが最も重要な制約です。サーバーが守れるのは、エージェントがこのサーバーを通してしか届かないものだけです。

### ユーザーの権限で動く

サーバーは、ルートとポリシーの範囲内で、ユーザーが読み書きできるものを読み書きできます。
許可ルールを誤って書くと、OS が本来許さないアクセスを与えてしまいます。
許可ルールは、権限の付与と同じくらい慎重に確認してください。

### ポリシーは起動時に一度だけ読む

ポリシーは起動時に読み込み、再読み込みはしません。変更には再起動が必要で、動いているサーバーは停止するまで古いポリシーのままです。

## 対応プラットフォーム

| プラットフォーム | 最小 | 仕組み |
|---|---|---|
| Linux | カーネル 5.6 | `RESOLVE_NO_SYMLINKS` 付きの `openat2` |
| macOS | 11 | `O_NOFOLLOW_ANY` 付きの `openat` |
| Windows | 対象外 | |

確認は起動時に行います。カーネルや seccomp プロファイルがこの呼び出しを拒否すると、要件を示したメッセージで起動を拒否します。
詳しくは [usage.ja.md](usage.ja.md#トラブルシューティング) を参照してください。

## 監査ログ

監査記録は、操作ごとに 1 行の JSON として標準エラー出力に出ます。MVP にはファイルへの出力オプションがありません。
MCP クライアントによって標準エラー出力の扱いが違うため、自分で取り込む必要があるかもしれません。
`--audit-log <file>` オプションは後の課題です。

## エラーコード

ツールのエラーは、構造化出力に次の安定したコードのいずれかを入れます。

| コード | 発生条件 |
|---|---|
| `invalid_argument` | 引数が欠けている、または型が違う。パスが検証に失敗した。 |
| `policy_denied` | ポリシーが操作を拒否した。`rule` フィールドに deny ルール名が入る。既定拒否の場合は空。ファイルがあるかどうかに関係なく返る。 |
| `not_found` | ポリシーでは許可されたが、対象が存在しない。 |
| `size_limit_exceeded` | 読み書きが設定したサイズ上限を超えた。 |
| `unsupported_file_type` | symlink、デバイス、FIFO、ソケットなど、通常ファイル以外が対象。 |
| `is_directory` | ファイル操作の対象がディレクトリだった。 |
| `not_a_directory` | `list_files` の対象がディレクトリでない、または親がディレクトリでない。 |
| `unsupported_content` | ファイルが有効な UTF-8 でない。 |
| `permission_denied` | ポリシーでは許可されたが、OS が操作を拒否した。 |
| `internal_error` | 予期しない失敗。操作は実行していない。 |

## 問題の報告

疑わしい迂回は、GitHub リポジトリに issue を立てて報告してください。
ポリシー、リクエスト、観測された結果を含めてください。ファイルの内容は取り除いてください。
